# 계정 로그인과 세션

## 구현 범위

기존 SENSTA 이메일·비밀번호 계정으로 로그인하고, 내 공개 프로필로 이동하며, 로그아웃한다.
피드 우상단 로그인 화살표 또는 내 프로필 사진에서 iOS 기본 Form 시트를 연다.
계정 이름 옆에도 기존 `profile` 응답의 사진을 표시하며, 사진이 없거나 로딩에 실패하면 기본 인물
아이콘을 표시한다. 시트는 절반 높이·시스템 블러로 시작하고 입력·프로필 탐색 때 확장한다.
접근성 큰 글자에서는 전체 높이를 사용하며, 투명도 줄이기 설정이면 불투명 배경으로 전환한다. 공개 사진 감상은 로그인 없이 유지한다.
게시글 상세에서 좋아요·취소를 제공하고 피드에 수치를 공유한다. 본문 아래에서 댓글 작성·답글과
댓글 좋아요·취소와 본인 댓글 수정·삭제를 제공한다. Google 로그인은 설정이 준비된 빌드에서 공식
Google 버튼으로 제공한다. Apple 로그인, 회원가입·비밀번호 재설정은 후속 기능이다.

## 기존 Android/GOAPI 계약

| 동작 | 요청 | 처리 |
| --- | --- | --- |
| 로그인 | `POST /auth/signin`, form `id`, `password` | `uid`, `name`, `id`, `blocked`, `token`, `refresh` |
| Google 로그인 | `POST /auth/android/google`, form `id_token` | Android와 같은 Web client audience를 검증하고 같은 token 쌍 반환 |
| 세션 확인 | `GET /auth/load`, Bearer access token | 존재하는 비차단 계정만 로그인 상태로 표시 |
| 토큰 갱신 | `POST /auth/android/refresh`, JSON `refresh` | access/refresh 쌍을 교체한 뒤 세션 확인 재시도 |
| 로그아웃 | `POST /auth/logout`, Bearer access token | 로컬 삭제 성공 후 서버에도 폐기를 요청 |

GOAPI와 Android·NUBO 요청 계약은 변경하지 않는다. 로그인 비밀번호는 해시하거나 공백을 제거하지
않으며 HTTPS form으로 전달한다. 이메일 양끝 공백만 제거한다. `/auth/android/refresh`는 플랫폼 검사가
없는 기존 네이티브 계약이다. 서버가 사용자별 refresh token을 관리하는 기존 정책도 그대로 따른다.

Google 공식 iOS SDK가 iOS client ID로 인증 화면을 열고 Web 유형 server client ID를 audience로 하는
ID token을 GOAPI에 전달한다. server client ID는 Android의 `google_web_client_id` 및 운영
`OAUTH_GOOGLE_ANDROID_CLIENT_ID`와 같아야 한다. 앱은 access/refresh 쌍을 Keychain에 저장하기 전에는
로그인 계정을 화면에 공개하지 않는다. client ID 설정이 없는 빌드에서는 Google 버튼을 숨기며 이메일
로그인에는 영향을 주지 않는다. ID token은 로그나 저장소에 기록하지 않는다.

## 저장과 오류 복구

- access/refresh 쌍만 API base URL과 bundle ID로 구분한 Keychain 단일 항목에 저장한다.
  `WhenUnlockedThisDeviceOnly`를 사용해 기기 간 동기화·백업 이동을 하지 않는다.
- 사용자 정보는 메모리에만 유지하고 비밀번호는 요청 직후 입력란에서 지운다.
- 인증 URLSession은 ephemeral이며 쿠키·디스크 캐시·HTTP 리다이렉트를 사용하지 않는다.
- 앱 시작 시 저장된 access token으로 계정을 확인하고, HTTP 401일 때만 refresh를 한 번 시도한다.
  회전된 토큰은 후속 계정 조회 전에 저장한다. 중복 세션 작업은 실행하지 않는다.
- 통신 실패는 저장된 세션을 보존하고 재시도를 제공한다. 서버가 만료·무효 토큰을 거부하면 삭제하고
  다시 로그인을 요청한다. 차단 계정은 로그인 완료로 표시하지 않는다.
- Keychain 저장·삭제 실패를 성공으로 표시하지 않는다. 로그아웃 시 로컬 삭제가 먼저 완료되며,
  오프라인이면 서버 폐기는 완료되지 않을 수 있다. 서버의 access token 만료 정책은 유지한다.
- 공개 콘텐츠 조회는 익명으로 유지한다. 상세의 좋아요 컨트롤은 별도의 인증된 `/board/view`로
  개인별 상태와 게시판·게시글 UID를 대조한다. `/board/like`에는 `boardUid`, `postUid`, `liked`만
  전달하고 사용자 UID는 서버의 JWT에서 얻는다.
- 인증 요청은 설정된 API 범위로만 전달한다. 동시에 여러 요청이 401이면 refresh를 합치고 저장한
  새 쌍으로 한 번 재시도한다. 로그아웃·만료 이후의 요청과 응답은 이전 계정 상태를 복원하지 않는다.
- 좋아요 처리 중 중복 탭을 막고 서버 성공 뒤 하트·숫자를 갱신한다. 상세·피드는 세션 내 수치를
  공유한다. 응답 유실·권한 오류 등 실패 시 숫자를 성공으로 바꾸지 않으며 다음 조작 전에 상태를
  다시 조회한다. 로그인 시트를 닫았다고 자동으로 좋아요를 전송하지 않는다.

## 댓글 작성과 답글

- 기존 `POST /comment/write` form의 `boardUid`, `postUid`, `content`를 사용한다.
  답글은 `POST /comment/reply`에 실제 대상 댓글의 `replyTargetUid`를 추가한다.
  작성자 UID·권한은 서버가 JWT에서 확인한다.
- Android와 같이 양끝 공백을 제거한 뒤 UTF-16 길이 10 이상인 내용을 전송한다. 서버의 내용 정제,
  작성 권한·차단 계정·게시글/댓글 범위 검증은 그대로 적용된다.
- 양수 댓글 UID의 성공 응답 이후에만 초안을 비우고 목록과 피드/상세 댓글 수에 반영한다.
  목록 재조회 실패나 페이지 이동으로 아직 내려오지 않은 새 댓글은 화면에서 유지하며 UID로 중복을 제거한다.
- 전송 중 입력·대상 변경·중복 등록을 막는다. 서버 거부 시 초안과 답글 대상을 유지한다.
  네트워크 오류나 응답 해석 실패는 자동 재전송하지 않고, 목록에서 등록 여부를 확인한 뒤 명시적으로
  재시도할 수 있다. 초안은 현재 상세 화면의 메모리에만 있으며 계정 변경 때 지운다.
- 로그인 자체로 댓글을 전송하지 않는다. 삭제된 댓글에는 답글 버튼을 표시하지 않는다.
- 로그인하면 댓글 목록을 Bearer token으로 다시 읽어 개인별 `liked`를 확인한다. 확인된 상태에서만
  `PATCH /comment/like`에 `boardUid`, `commentUid`, `liked`를 보내며 사용자 UID는 서버가 JWT에서
  가져온다. 성공 응답 뒤 하트·숫자를 갱신하고, 결과 유실 시 목록 재조회 전에는 다시 토글하지 않는다.
  로그아웃·계정 변경 시 이전 계정의 채워진 하트를 즉시 지운다.

## 본인 댓글 수정과 삭제

- 댓글 작성자 UID가 현재 로그인 계정 UID와 같을 때만 좋아요 옆에 44pt 이상의 `수정`·`삭제` 버튼을
  표시한다. 서버도 JWT의 사용자 UID로 작성자 또는 관리자 권한을 다시 검사하며 클라이언트는 사용자
  UID를 보내지 않는다.
- 수정은 기존 `PATCH /comment/modify` JSON의 `boardUid`, `postUid`, `modifyTargetUid`, `content`를
  사용한다. Android와 같이 양끝 공백을 제거한 UTF-16 길이 2 이상을 요구하고 `&`, `<`, `>`, 큰따옴표,
  작은따옴표를 HTML 문자 참조로 바꿔 보낸다. 성공한 뒤에만 목록 내용을 바꾸며 실패하면 편집 초안을
  유지한다.
- 삭제는 기존 `DELETE /comment/remove`의 `boardUid`, `removeTargetUid` query를 사용한다. 답글이 있는
  원댓글은 서버 규칙대로 `삭제된 댓글입니다.` 자리를 남기고 답글과 댓글 수를 유지한다. 답글이 없거나
  답글 자체를 지우면 목록과 피드·상세 댓글 수에서 하나를 뺀다.
- 삭제 결과를 알 수 없는 통신 오류는 자동 재전송하지 않는다. 댓글 목록을 새로 읽어 상태를 확인한 뒤에만
  다시 삭제할 수 있으며, 로그아웃·계정 변경 뒤 늦게 도착한 수정·삭제 응답은 반영하지 않는다.

## 실기기 QA

피드 우상단 로그인 아이콘 → 기존 이메일 로그인 → 내 공개 프로필 → 앱 종료·재실행 → 계정 복원 →
로그아웃을 확인한다. 로그인 실패·통신 단절 시 기존 사진 감상이 유지되는지도 확인한다.
실제 계정 비밀번호는 제품 소유자가 iPhone에서 직접 입력한다.

Google QA: 비로그인 계정 시트 → Google 버튼 → 계정 선택 → 기존 Android Google 계정으로 로그인 →
피드 프로필 사진 확인 → 앱 종료·재실행 후 세션 복원 → 로그아웃을 확인한다. 취소했을 때 오류 문구가
남지 않는지, 다른 audience의 token과 미인증 이메일이 거부되는지도 확인한다.

댓글 QA: 사진 상세 → 댓글 영역 → 10자 이상 입력 시 길이 안내가 사라지는지 확인 → 등록 → 목록·피드
댓글 수 확인 → 댓글의 답글 버튼 → 대상 이름 확인 → 답글 등록 → 댓글 좋아요·취소를 확인한다. 본인
댓글 아래 좋아요 옆 수정 버튼으로 편집하고, 답글이 달린 원댓글 삭제 시 자리와 답글이 유지되는지 확인한다. 답글을
삭제했을 때 목록과 피드 댓글 수가 함께 줄어드는지도 확인한다.
네트워크를 끊었을 때 초안이 유지되는지, 결과 확인 안내가 표시되는지도 확인한다. 운영 댓글 작성과
좋아요는 제품 소유자가 직접 수행한다.
